# Cheatsheet: Building an In-App Bugs, Issues & Feature Backlog Page

This guide outlines how to build a complete, self-contained **Bugs, Issues & Feature Request Backlog Page** directly into your React / TypeScript web application.

---

## 1. Core Architecture & Data Model

Define clean TypeScript interfaces for issue items, severity, criticality (priority), category, and status.

```typescript
// types/issues.ts

export type IssueCategory = 'BUG' | 'FEATURE' | 'ENHANCEMENT' | 'UI_UX' | 'PERFORMANCE';
export type IssueSeverity = 'LOW' | 'MEDIUM' | 'HIGH' | 'CRITICAL';
export type IssueCriticality = 'P3_LOW' | 'P2_MEDIUM' | 'P1_HIGH' | 'P0_BLOCKER';
export type IssueStatus = 'OPEN' | 'IN_PROGRESS' | 'RESOLVED' | 'CLOSED';

export interface IssueItem {
  id: string;            // Unique ID e.g. "ISSUE-101"
  title: string;         // Short summary
  description: string;   // Steps to reproduce or detailed context
  category: IssueCategory;
  severity: IssueSeverity;
  criticality: IssueCriticality;
  status: IssueStatus;
  reportedBy: string;    // Reporter name or role
  createdAt: string;     // ISO timestamp
  updatedAt: string;     // ISO timestamp
  tags: string[];        // Array of tag keywords e.g. ["Speech", "UI"]
  votes: number;         // Upvote tally for priority sorting
}
```

## 2. Severity vs Criticality Matrix

Distinguish between **Impact (Severity)** and **Priority (Criticality)** to accurately triage backlog items:

| Dimension | Levels | Purpose |
| :--- | :--- | :--- |
| **Severity** | `LOW` • `MEDIUM` • `HIGH` • `CRITICAL` | Measures technical impact (e.g., cosmetic glitch vs system crash / data loss). |
| **Criticality** | `P3_LOW` • `P2_MEDIUM` • `P1_HIGH` • `P0_BLOCKER` | Measures triage urgency and sprint scheduling (e.g., P0 must fix immediately). |

## 3. Priority Rank Sorting Calculation

Calculate a numeric priority score to sort critical blockers and high-impact issues to the top of the backlog:

```typescript
const severityRank: Record<IssueSeverity, number> = {
  CRITICAL: 4,
  HIGH: 3,
  MEDIUM: 2,
  LOW: 1
};

const criticalityRank: Record<IssueCriticality, number> = {
  P0_BLOCKER: 4,
  P1_HIGH: 3,
  P2_MEDIUM: 2,
  P3_LOW: 1
};

// Priority score formula: (Criticality * 10) + Severity
const sortedIssues = [...issues].sort((a, b) => {
  const scoreA = criticalityRank[a.criticality] * 10 + severityRank[a.severity];
  const scoreB = criticalityRank[b.criticality] * 10 + severityRank[b.severity];
  return scoreB - scoreA;
});
```

## 4. Key React Component Features

A production-ready issue tracker component should include:

1. **Submission Modal / Drawer**: Form with input fields for title, description, category, severity, criticality, reporter name, and comma-separated tags.
2. **Multi-Criterion Filter Bar**:
   - Live search input across title, description, author, and tags.
   - Dropdowns for Category, Severity, Criticality Priority, and Status (`OPEN`, `IN_PROGRESS`, `RESOLVED`, `CLOSED`).
   - Sort toggle: `Highest Priority`, `Most Votes`, or `Newest First`.
3. **Upvoting & Quick Triage**:
   - `+1` Upvote button to crowdsource feature popularity.
   - Quick inline status updater dropdown on each issue item.
4. **Persistence & Export**:
   - `localStorage` fallback for offline / local-first storage.
   - `JSON` export button to backup or sync backlog data across teams.

## 5. Sample React Component Implementation

```tsx
import React, { useState, useEffect } from 'react';
import type { IssueItem, IssueCategory, IssueSeverity, IssueCriticality, IssueStatus } from './types/issues';

const STORAGE_KEY = 'LPC_USER_ISSUES_BACKLOG';

export function IssueTrackerPage() {
  const [issues, setIssues] = useState<IssueItem[]>(() => {
    try {
      const stored = localStorage.getItem(STORAGE_KEY);
      return stored ? JSON.parse(stored) : [];
    } catch {
      return [];
    }
  });

  useEffect(() => {
    localStorage.setItem(STORAGE_KEY, JSON.stringify(issues));
  }, [issues]);

  const handleStatusChange = (id: string, newStatus: IssueStatus) => {
    setIssues(prev => prev.map(item => item.id === id ? { ...item, status: newStatus } : item));
  };

  const handleUpvote = (id: string) => {
    setIssues(prev => prev.map(item => item.id === id ? { ...item, votes: item.votes + 1 } : item));
  };

  return (
    <div className="p-6 max-w-7xl mx-auto space-y-4">
      <h2 className="text-xl font-bold">In-App Issue & Feature Backlog</h2>
      {/* Render Filter Bar, Form Modal, and Issue List Cards here */}
    </div>
  );
}
```
